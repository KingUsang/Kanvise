# **HERO / FIRST EXPERIENCE** 

The first screen should be highly visual and interactive. 

We can show a tutor surrounded by or interacting with the different tools they currently use. 

The individual tools should be recognisable, but we should **not copy the visual designs of existing products or recreate their interfaces directly.** 

Instead, use visual representations of what each tool represents. 

For example: 

#### **Zoom / Google Meet** 

→ Live teaching 

#### **Google Drive** 

→ Materials 

#### **Google Forms** 

→ Assessments 

#### **WhatsApp** 

→ Communication 

#### **Payment tools** 

→ Collections 

#### **Spreadsheets** 

→ Tracking 

The visitor should be able to interact with these elements. 

As they click or hover over each one, it should reveal: 

#### **what they currently use it for** 

and gradually show how many separate tools are required to run one tutorial. 

The experience should create the realisation: 

**“I'm using all of these just to run my classes.”** 

Then the separate elements begin coming together. 

This transition should lead naturally into Kanvise.

# **THE BIGGER IDEA** 

After the product has been demonstrated, explain the problem briefly. 

The problem is not simply that tutors use too many applications. 

The deeper problem is that the online tutoring experience is fragmented. 

Tutors are teaching in one place: Managing students somewhere else Collecting payments somewhere else Sending materials somewhere else.Running assessments somewhere else. Tracking performance manually. 

Kanvise brings these parts together into one environment. 

And beyond bringing them together, Kanvise is designed to help tutors **understand what is happening with their students.** 

This is where we establish the positioning: 

# **Kanvise is the infrastructure for smart tutoring.** 

This should be communicated confidently and simply.

# **FAQs - Select, add or remove from this list** 

### **What exactly is Kanvise?** 

**Kanvise is a workspace for smarter tutoring. It brings the tools and workflows tutors need to teach, manage their classes, assess students and understand their performance into one place.** 

### **Who is Kanvise built for?** 

**Kanvise is built for online tutors and tutorial providers who want to spend less time juggling tools and more time focused on teaching and their students.** 

### **What can I actually do on Kanvise?** 

**You can run live classes, create rooms, manage students, share assignments, run assessments and mocks, track student performance and get insights that help you understand what is happening in your classroom.** 

**Is Kanvise just another platform for hosting classes?** 

**No. Hosting classes is only one part of it. Kanvise is designed around the entire tutoring experience, from running the class to understanding how your students are actually doing.** 

### **Why not just use Zoom, WhatsApp and Google Drive?** 

**You can. Most tutors already do. The problem is having to move between different tools to run one tutoring experience. Kanvise brings those workflows together so they can work as one system.** 

### **Is Kanvise available yet?** 

**Kanvise is currently being used by educators in our pilot. We are gradually opening access as we continue building and improving the workspace.** 

### **What happens when I join the waitlist?** 

**You'll receive your position on the waitlist immediately after joining. We'll also keep you updated as Kanvise moves closer to wider access.** 

### **Can I see Kanvise before joining?** 

**Yes. You can explore the product and see how Kanvise works through the interactive demo on this website before joining the waitlist.** 

### **When will I get access?** 

**Access will be opened in stages. Your place on the waitlist determines when you're considered for access as we expand availability.** 

### **How can I follow what you're building?** 

**We're building Kanvise in public. Follow us on LinkedIn, Instagram and our other social platforms for product updates, new features and the journey behind Kanvise.**
