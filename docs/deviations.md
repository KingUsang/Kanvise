- Review follow-up (2026-11-20): the five web callers that bypassed `authenticatedFetch` (direct-assignments page, `PreparingClassroom`, `push-notifications`, dashboard sidebar badge) now send `X-Kanvise-Account-Id` through `accountContextHeaders()` in `web/src/lib/account-preference.ts`. Server-rendered student pages cannot read `sessionStorage`, so `standaloneAwareAccountContext` falls back to the learner's single active membership when the header is absent (no membership and no profile account stays the standalone-mock path; several memberships still need the header). A server-rendered page for a learner with several accounts therefore still gets 400 until the selected account is sent in a cookie; owner decision needed. Addressed by DEV-ACC-005 (owner chose the cookie): the selection is now in the `kanvise_account` cookie and several memberships return `ACCOUNT_SELECTION_REQUIRED`, which opens the account picker.
- Review follow-up: `studentMocksRouter` is now mounted before `mocksRouter` in `api/src/index.ts`. Before this, `mocksRouter`'s router-wide strict account context shadowed the standalone-aware preflight and attempt routes (confirmed by `student-mocks-mount-order.test.ts`, which fails with the old order). This makes the DEV-SEC-006 standalone `knownGap` claim true for those two routes.
